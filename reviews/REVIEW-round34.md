# Review Round 34 — Choice-Order Analysis and BoolQ Benchmark

**Reviewed revisions:** `0f52a04` (`benchmarks: implement choice-order robustness & latency breakdown (R33 Option A)`) and `62d9f92` (`benchmarks: import and evaluate BoolQ reading comprehension (150 items)`).

**Scope:** Review of the new analysis utility, benchmark importer and fixtures, and the conclusions added to `specs/denoising.md`. No runtime code was changed as part of this review.

## Findings

### R34-01 — The ARC analysis does not establish decision invariance

**Severity: High — correct the interpretation before relying on it.**

In `specs/denoising.md` §8.5, the McNemar result for base T2 versus rotated T2 is described as demonstrating that performance is statistically invariant to option order. McNemar's test here compares paired *correct/incorrect outcomes*. It does not test whether the selected answer content stayed the same. The saved results report identical selected content for 120 of 150 examples (80%), so one in five choices changed even though aggregate accuracy was similar.

A non-significant difference test is also not an equivalence test: it does not establish that any accuracy difference is small enough to be practically irrelevant. One cyclic rotation is useful exploratory evidence but cannot establish robustness across option orderings.

**Recommendation:** Describe the 80% content agreement and paired correctness transitions directly. If making an invariance claim, evaluate several deterministic permutations and predefine an acceptable equivalence margin for both content agreement and accuracy; report confidence intervals and an equivalence analysis against that margin.

### R34-02 — The reported latency breakdown is not backed by stage-level measurements

**Severity: High — relabel or instrument before treating these as measured components.**

Section 8.6 calls the approximately 880 ms prompt prefill and 180 ms canvas evaluation “isolated” by profiling. The new result artifacts record aggregate request latency, and the reviewed changes add no per-stage timing instrumentation or profiler output. The approximate sum of those figures matching the end-to-end latency does not establish that either component was measured independently. Likewise, the estimated step-two cost and the aggregate T2 overhead do not by themselves isolate canvas execution time.

**Recommendation:** Either provide the profiler capture or reproducible stage-timing output and measurement procedure, or label the split as an estimate with its derivation. Add timings around prefill and canvas execution, with the relevant GPU work synchronized before stopping each timer, and report repeated measurements and distributions.

### R34-03 — The “balanced” and “resolves position bias” conclusions overstate the letter counts

**Severity: Medium — revise the claims and use a controlled comparison.**

Section 8.5 calls the T2 selection distribution balanced and says self-conditioning resolves position bias, while the same table gives T2 letter frequencies of A 15.3%, B 20.7%, C 41.3%, and D 22.7%. C is still selected much more often than the other letters. For the base ARC slice, the gold-answer positions are A 39, B 42, C 42, and D 27; raw prediction-letter counts therefore need to be interpreted alongside the answer-position distribution and per-example remapping.

**Recommendation:** Report the observed frequencies without calling them balanced or resolved. Use paired per-item results across multiple rotations to measure whether predictions follow answer content or displayed position, and compare prediction counts with the corresponding gold-position counts.

### R34-04 — The BoolQ fixture silently truncates one passage

**Severity: Medium — preserve or disclose the altered example.**

`tools/import_benchmark.py` truncates passages after 300 whitespace-separated words. The checked-in `boolq_150.json` fixture contains one such passage, `boolq_55`, ending in an ellipsis. This changes the benchmark input and may remove supporting evidence. The fixture does not record that the passage was truncated or retain the original row metadata needed to identify the transformation.

**Recommendation:** Preserve the source passage if it fits the supported prompt, or explicitly record the original source index, truncation limit, and truncation flag in the fixture or companion provenance. Check prompt length using the actual tokenizer rather than a word-count proxy before asserting that an input fits the CUDA sequence limit.

### R34-05 — The paired-run analyzer does not produce the p-values cited in the report

**Severity: Medium — make the statistical results reproducible.**

`tools/compare_runs.py` labels its output as McNemar analysis but prints only a chi-squared statistic. The p-values in `specs/denoising.md` are not generated by this tool, so their calculation is not reproducible from the checked-in analysis command. In addition, the continuity-correction expression at line 85 squares `abs(b-c)-1` without clamping it at zero. When the discordant counts are equal and nonzero, that formula returns a positive statistic; the continuity-corrected numerator should be `max(0, abs(b-c)-1) ** 2`. For very small discordant counts, such as the BoolQ T1/T2 comparison, an exact paired test is preferable to relying on the asymptotic chi-squared approximation.

**Recommendation:** Correct the continuity correction and either compute and print the p-value (including the test variant) or stop labeling the output as a complete test. Report discordant counts. Add input checks for duplicate IDs and mismatched ID sets so that silent overwrites or partial overlap cannot produce misleading paired summaries.

### R34-06 — Published baseline scores are not directly comparable to this slice

**Severity: Low — qualify the contextual comparison.**

Section 9.3 compares Zeno's 150-item BoolQ validation slice with published Jev and Qwen scores. The report does not establish that those published scores used the same examples, split, prompt, or scoring protocol. They provide context, but do not support a direct head-to-head comparison.

**Recommendation:** Keep the figures only with an explicit note that the protocols and evaluated examples differ, or defer direct comparison until those systems are evaluated on the same frozen requests.

## Positive Changes

- The checked-in base and rotated ARC fixtures preserve the option remapping needed to inspect choice-order effects.
- BoolQ adds a relevant binary reading-comprehension task and records per-example results for both T1 and T2.
- On this BoolQ slice, T2 has lower accuracy and worse ECE, Brier score, and NLL than T1, while triggering additional work. The report appropriately identifies this as a contrast with ARC; keep the conclusion scoped to this sample and setup.

## Review Verdict

These additions are useful exploratory evaluations, but the choice-order and latency conclusions need the corrections above before they can support strong claims. In particular, correctness stability is not content invariance, aggregate latency is not a pipeline profile, and the BoolQ score is based on a slice with one truncated input. Preserve the artifacts, fix the analysis/reporting, and extend the controls before treating the results as general evidence.

## Verification Limits

The review inspected the two commits, their changed files, the paired-run script, and the checked-in ARC and BoolQ artifacts. No build, test suite, or new benchmark run was performed.
